# Writing Criteria

Every guide in this repo is written to the same
standard. If you're adding or editing a guide —
human or AI — hold it to these.

1. **Plain words, real ideas.** Simple language,
   never dumbed-down concepts. Explain jargon on
   first use; collect terms in the glossary.
2. **No hype.** No marketing adjectives, no
   "revolutionary," no promises about what
   something will do for the reader.
3. **Honest about limits.** Say what the thing
   *can't* do. State uncertainty instead of
   smoothing it over. Validation notes include
   what remains unverified.
4. **No invented numbers.** Benchmarks, defaults,
   and specs are either measured or qualified with
   "depends on your setup." If it wasn't tested,
   say so.
5. **Checkable.** Commands are meant to be run,
   with "Check:" blocks showing what success looks
   like. Sources are linked, not asserted.
6. **Respect the reader's setup.** Call out
   Windows/Mac/Linux differences. Don't assume a
   GPU, a budget, or prior experience.
7. **Safety isn't skipped.** Real risks get
   stated plainly, not buried.
8. **Scoped.** Each guide says what it covers and
   points elsewhere for the rest. No guide
   pretends to be the whole subject.
9. **Structure over prose.** Tables, before/after
   examples, symptom → fix. Scannable beats essay.

## Verification notes for this guide

Built and verified 2026-10-23 against
**OBS Studio 30.0.2** — Ubuntu 24.04's
packaged build (package version
30.0.2+dfsg-3build1; the binary reports
itself as `OBS Studio - 30.0.2.1-3build1`)
— on a virtual machine with 2 cores, no
camera, no microphone, no graphics
processor and no sound server. Where the
guide describes a newer release's
behaviour (for example Hybrid MP4
recordings), it says so in the chapter.

**The ceiling, stated plainly:** OBS is a
desktop GUI application with no headless
mode, and the bench had no devices and no
display. Everything the program exposes
without a human at its window — install,
command line, startup, the files it
generates, the files it reads — was
executed and read for real. Everything
behind the window — the wizard, recording,
streaming, filters in use — could not be,
and is documented only, as labelled
below. The transcripts are the evidence:
`obs-studio-lab/transcripts/`, t00–t05.

**Ran for real:**

- t00 — the install itself: `apt install
  obs-studio`, 153 packages newly
  installed, `dpkg` reporting the package
  installed and configured.
- t01 — `obs --version` and `obs --help`
  from the installed binary; every flag
  quoted in this guide (chapter 3,
  `examples/commands.txt`) is from that
  help text.
- t02 — three launch attempts. No
  display: Qt aborts, "Could not load the
  Qt platform plugin 'xcb'". Qt's offscreen
  platform: the program initialises,
  writes `global.ini`, a log and profiler
  data, then stops at "Unable to open X
  display". Under Xvfb (a virtual
  display): full startup — "Startup
  complete", the default scene created,
  base 1920x1080 / output 1280x720 / 30 fps
  in the log, the obs-websocket 5.3.4
  module loaded, and the honest bench
  limitations in the same log: no VAAPI,
  no PipeWire captures, and
  "v4l2loopback not installed, virtual
  camera disabled".
- t03 — the first-run configuration tree,
  generated by the program and read back:
  `global.ini`, `basic/profiles/Untitled/
  basic.ini`, `basic/scenes/Untitled.json`,
  `logs/`, `plugin_config/`,
  `profiler_data/`. The fresh profile's
  `basic.ini` held only its name. The
  `global.ini` `[OBSWebSocket]` section
  showed `ServerEnabled=false`,
  `ServerPort=4455`, `AuthRequired=true`
  and a server password the program
  generated on first load (redacted in
  the transcript).
- t04 — chapter 5's fixture as a file: a
  scene collection ("Community Meeting":
  four scenes, nine sources) constructed
  by hand as JSON, modelled field for
  field on the generated `Untitled.json`,
  installed into `basic/scenes/` and
  selected in `global.ini`. The program
  loaded it: its log records every source
  created and "Switched to scene 'Title'".
  The one failure was environmental and
  expected — the v4l2 camera source could
  not open a device, because the bench
  has no camera. A load-only run did not
  rewrite the file.
- t05 — portable mode probed: `obs
  --portable` on this packaged Linux
  build is accepted but inert — the log
  answers "Portable mode: false" and the
  configuration goes to `~/.config/
  obs-studio` as usual. Chapter 11 says
  so, and describes the portable desk as
  the Windows .zip-build feature it is.

**Documented only, and labelled as such
in the chapters:** the
Auto-Configuration Wizard's interview and
benchmarks (chapter 4); building scenes
in the window itself (chapter 5); audio
devices, meters and filters in use
(chapter 6 — the bench has no audio
hardware and no sound server); recording
in every format, remuxing and the replay
buffer (chapter 7); streaming to any
service, ingest choice and dropped-frame
behaviour against a real connection
(chapter 8 — the bench streamed nothing,
to anywhere); effect filters, transitions
and the virtual camera in use (chapter 9
— its Linux prerequisite's absence was
verified, its use was not); driving OBS
from another program over obs-websocket
(chapter 10 — the module's load and its
configuration were verified, no client
connected); and Studio Mode throughout.
Windows- and macOS-specific behaviour
(permissions, the platform encoders,
the portable .zip build) is described
from the project's documentation for
those platforms, not from a bench on
them.

**Fixtures:** the Community Meeting
scene collection — Title, Speaker and
Slides, Slides Only, Break, over a
colour background, two text sources, a
slides image and a camera — is invented
for this guide, as are the podcast and
lesson setups in chapters 5 and 12. No
real meeting, organisation or person
appears in them. The websocket password
the lab program generated appears in no
transcript; the lab's scratch
configuration was discarded with the
lab.
